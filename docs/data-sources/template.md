# zabbix_template (Data Source)

Looks up an existing Zabbix template by technical name or display name.

## Example Usage

```terraform
data "zabbix_template" "linux" {
  host = "Linux by Zabbix agent"
}

resource "zabbix_host" "example" {
  host      = "server-1.example.com"
  groups    = [data.zabbix_hostgroup.linux_servers.id]
  templates = [data.zabbix_template.linux.id]

  interface {
    type = "agent"
    ip   = "10.0.0.10"
  }
}

data "zabbix_hostgroup" "linux_servers" {
  name = "Linux servers/production"
}
```

## Schema

### Optional

- `host` (String) Technical template name. Give one of `host` or `name`
- `macro` (Block Set) User macros defined on this object (unordered). Zabbix replaces the whole macro collection on update, so omitting a macro removes it. (see [below for nested schema](#nestedblock--macro))
- `name` (String) Template display name. Give one of `host` or `name`

### Read-Only

- `description` (String) Template description
- `groups` (Set of String) Group IDs this template belongs to. On Zabbix 6.2 and later these are template group ids (zabbix_templategroup); on 6.0/6.1 they are host group ids (zabbix_hostgroup).
- `id` (String) The ID of this resource.
- `readme` (String) Template readme text, shown by the template wizard. Requires Zabbix 7.4 or later.
- `templates` (Set of String) IDs of templates linked into this one
- `uuid` (String) Template UUID, generated by Zabbix
- `vendor_name` (String) Template vendor name. Requires Zabbix 6.4 or later, and must be set together with vendor_version.
- `vendor_version` (String) Template vendor version. Requires Zabbix 6.4 or later, and must be set together with vendor_name.
- `wizard_ready` (Boolean) Whether the template is ready to be offered by the template wizard. Requires Zabbix 7.4 or later.

### Nested Schema for `macro`

Required:

- `name` (String) Macro name, in Zabbix's `{$NAME}` form
- `value` (String) Macro value. For `type = "vault"` this is the vault path, `path/to/secret:key`. A `secret` value is write-only in the Zabbix API: it is kept from configuration, a change made to it outside Terraform is not detected, and an imported secret macro reads back with an empty value. The attribute is not marked sensitive; pass a secret from a sensitive variable or data source and Terraform masks it in plan output

Optional:

- `description` (String) Macro description
- `type` (String) Macro type, one of: secret, text, vault

Read-Only:

- `id` (String) Macro ID (hostmacroid), assigned by Zabbix
