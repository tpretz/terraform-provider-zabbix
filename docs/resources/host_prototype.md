# zabbix_host_prototype (Resource)

Manages a Zabbix host prototype: the template an LLD discovery rule uses to create a real host for each entity it finds (e.g. one host per discovered virtual machine). Does not yet cover inventory_mode, custom interfaces, macros, or proxy/monitored_by assignment -- none of those are expressible here.

## `group` and `group_prototype` are sets

Like a host's `interface` or `templates`, `group` and `group_prototype` are
unordered `TypeSet` collections: writing them in a different order is not a
change, and set elements cannot be indexed (`group[0]` does not parse).

## Scope

This resource does not cover `inventory_mode`, custom interfaces, macros, or
proxy/`monitored_by` assignment on discovered hosts -- none of those are
expressible here yet.

## Example Usage

```terraform
data "zabbix_host" "example" {
  host = "vcenter.example.com"
}

data "zabbix_hostgroup" "virtual_machines" {
  name = "Virtual machines"
}

# Zabbix's own VMware monitoring discovers virtual machines with the
# agent-polled "vmware.vm.discovery" key; this fixture uses a trapper rule
# instead, since this provider has no zabbix_lld_vmware resource yet.
resource "zabbix_lld_trapper" "vms" {
  hostid = data.zabbix_host.example.id
  name   = "Virtual machine discovery"
  key    = "vmware.vm.discovery"
  delay  = "0"
}

# host, group_prototype and tag follow the Zabbix API reference's own
# hostprototype.create example:
# https://www.zabbix.com/documentation/current/en/manual/api/reference/hostprototype/create
resource "zabbix_host_prototype" "vm" {
  ruleid = zabbix_lld_trapper.vms.id
  host   = "{#VM.NAME}"
  group  = [data.zabbix_hostgroup.virtual_machines.id]

  group_prototype {
    name = "{#HV.NAME}"
  }

  tag {
    key   = "datacenter"
    value = "{#DATACENTER.NAME}"
  }
}
```

## Schema

### Required

- `group` (Set of String) Host group IDs every discovered host is placed into (unordered). At least one is required -- this is Zabbix's groupLinks
- `host` (String) Technical name pattern for discovered hosts, may contain {#MACRO} placeholders from the discovery rule, e.g. "{#VM.NAME}"
- `ruleid` (String) ID of the discovery rule this host prototype belongs to. Changing it replaces the prototype

### Optional

- `discover` (Boolean) Whether this prototype keeps discovering new hosts. Set to false to stop discovering new ones and mark previously discovered hosts as lost, without deleting the prototype itself
- `enabled` (Boolean) Whether discovered hosts are monitored. A disabled host prototype still discovers hosts, but they are created unmonitored
- `group_prototype` (Block Set) Dynamic host group name patterns (unordered), e.g. `{ name = "{#HV.NAME}" }`. Every host this prototype discovers is placed into a group named by substituting that host's LLD macro values, in addition to the static groups named in `group` (see [below for nested schema](#nestedblock--group_prototype))
- `name` (String) Visible name pattern for discovered hosts. Defaults to `host` when empty, same as zabbix_host and zabbix_template
- `tag` (Block Set) Tags applied to this object (unordered). Tags are how Zabbix 5.4 and later group and filter objects; they replaced applications. Zabbix replaces the whole tag collection on update, so omitting a tag removes it. (see [below for nested schema](#nestedblock--tag))
- `template` (Set of String) Template IDs linked to every discovered host (unordered). Removing one here unlinks and clears it

### Read-Only

- `id` (String) The ID of this resource.
